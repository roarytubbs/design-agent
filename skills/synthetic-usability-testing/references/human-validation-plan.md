# Human Validation Plan

Use this reference to turn synthetic usability risks into practical human validation.

Synthetic testing can reveal likely risks. Human validation determines whether real users experience those risks, how often, and why.

## Method Selection

Choose a method based on the decision the team needs to make:

| Goal | Useful Method |
|---|---|
| Understand why a task fails | Moderated usability test |
| Measure task success or drop-off | Unmoderated usability test or analytics funnel |
| Compare two solution directions | Prototype comparison or preference test |
| Validate language and comprehension | Five-second test, first-click test, or interview probe |
| Check prevalence across a broader audience | Survey or product analytics |
| Learn from existing data before recruiting | Existing evidence audit |

## Minimum Validation Plan

Every report should include:

- Decision: what the team needs to decide.
- Riskiest synthetic finding: the issue most worth validating.
- Participants: who needs to test it.
- Tasks: what participants will try to do.
- Success criteria: what counts as completion.
- Metrics: task success, time on task, error rate, confidence, support need, or drop-off.
- Confirming evidence: what would support the finding.
- Falsifying evidence: what would prove the synthetic finding was wrong or overstated.

## Existing Evidence Audit

Before recruiting, check whether useful signal already exists:

- Analytics or funnels.
- Support tickets or help requests.
- Sales, success, or community feedback.
- Session recordings.
- Prior research notes.
- App reviews, docs feedback, or issue trackers.

Label signal strength:

- Strong: repeated across independent sources or supported by behavioral data.
- Medium: repeated in one source or directly observed in the artifact.
- Weak: plausible but based mostly on heuristic review or synthetic persona simulation.

## Instrumentation Ideas

Consider tracking:

- Task start.
- Task success.
- Drop-off by step.
- Error shown.
- Error recovered.
- Help or docs opened.
- Backtracking.
- Undo or cancel usage.
- Repeat use.
- Time to first success.

Instrumentation should avoid collecting secrets, sensitive personal data, or unnecessary content.
